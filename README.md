# slidecraft

Build slide decks as code, and catch the layout defects that source review cannot see.

A deck here is one HTML file on a fixed canvas, rendered to PDF and to one PNG per slide by a
headless browser. Diagrams are generated by small Python scripts. `slides check` opens the result in
a browser, measures it, and reports text that overflows a slide, labels sitting on each other,
type too small to read, weak contrast and resources that will not load offline.

```bash
npm i -D playwright && npx playwright install chromium

node bin/slides.mjs new my-deck --theme=default
node bin/slides.mjs render my-deck --png     # my-deck/deck.pdf and my-deck/preview/*.png
node bin/slides.mjs check my-deck            # layout defects, with a non-zero exit on errors
```

Then open `my-deck/preview/` and look at every slide. That step is the method; everything else is
tooling.

## Why

Most decks are built by dragging boxes, so they cannot be diffed, reviewed, regenerated or tested,
and defects are found in the room. Making the deck text and the diagrams code fixes the first four.
An automated checker fixes the fifth for the defects a machine can measure, which frees a person's
attention for the ones it cannot: whether the deck is true, and whether it makes its point.

## What is in here

| Path | What it is |
|---|---|
| `bin/slides.mjs` | CLI: `new`, `render`, `check`, `inject`, `tokens`, `themes`, `kits` |
| `src/` | renderer, checker, scaffolder |
| `themes/` | `default`, `dark`, `high-contrast`. Tokens are data; replace them |
| `kits/python/slidekit/` | diagram kits: `blocks`, `flow`, `platforms`, `graph`, `timeline` |
| `templates/deck/` | the deck shell you get from `slides new` |
| `examples/` | two complete decks, invented content, different themes and kits |
| `docs/` | the method, layouts, diagrams, theming, checks, accessibility, alternatives |
| `.claude/skills/slide-design/` | instructions so an AI coding agent follows the same procedure |

## Opinions, and where they stop

Held: one message per slide; facts that trace to a source; an archetype instead of an improvised
layout; one accent colour; status colours reserved for status; look at every rendered slide.

Not held: a house style. The bundled themes disagree with each other on purpose, the kits are
separate visual languages rather than one look, and `docs/alternatives.md` says plainly when
PowerPoint, Marp, reveal.js, Quarto or Beamer is the better tool. Nothing here is a template you
are supposed to keep; the tokens, kits and layouts are meant to be replaced.

## Requirements

Node 18+, Playwright with Chromium, Python 3.9+ for diagrams (no packages). Fonts are yours to
supply: put files you are licensed to embed in `assets/fonts/`.

## Non-goals

Live presenting with transitions, real-time collaboration, `.pptx` editing, and a template gallery.
Export to images works anywhere; if you need those, `docs/alternatives.md` points you elsewhere.
