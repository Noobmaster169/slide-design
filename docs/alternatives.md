# When something else fits better

This repo is one engine and one method. It is not the right choice for everything.

| Tool | Better when |
|---|---|
| PowerPoint, Keynote, Google Slides | your organisation edits decks collaboratively in those tools, or a template is mandated |
| Marp, Slidev, reveal.js, remark | you want Markdown-first authoring, speaker notes and a web presenter with live transitions |
| Quarto, R Markdown, Jupyter | the deck is generated from analysis and should re-run with the data |
| LaTeX Beamer | heavy mathematics and academic conventions |
| Figma, Canva, Illustrator | a designer is working visually, and the deck is a one-off artefact |
| Excalidraw, Mermaid, Graphviz, D3 | you need a specific diagram form; export SVG and embed it here |

**What transfers regardless of tool:** one message per slide, verified facts, an archetype rather
than an improvised layout, one accent colour, reserved status colours, a type scale, and looking at
every rendered slide before presenting. The checker is the only part that needs this engine, and
its rules are worth applying by eye anywhere.

**What this engine gives you that most of the above do not:** the deck is text in git, the diagrams
are generated by code you can re-run, and layout defects are caught automatically in CI.
